## Project Overview

A Rust-based Kubernetes ACME HTTP-01 challenge solver that integrates with cert-manager. It watches Challenge CRDs and serves ACME challenge responses, acting as a custom HTTP-01 solver for cert-manager's certificate issuance flow.

## Deployment

Building and deploying the Docker image is the only supported workflow — there is no local run path.

```bash
# Build (default: Kubernetes v1.35)
cargo build --release

# Build for a specific Kubernetes version
cargo build --features v1_31 --release   # supports v1_31 through v1_35

# Docker build
docker build --build-arg K8S_VERSION=v1_35 .
```

Check and lint: `cargo check` / `cargo clippy`. There are currently no tests.

## End-to-End Challenge Flow

1. cert-manager needs an HTTP-01 challenge to issue a certificate
2. cert-manager creates a `Challenge` CR in the watched namespace and a solver Pod + Service (labeled `acme.cert-manager.io/http01-solver=true`) to serve the key authorization
3. The challenge controller sees the new Challenge CR and stores it in shared `LastSeen` state
4. The ACME CA (e.g. Let's Encrypt) makes a `GET /.well-known/acme-challenge/{token}` request to this server
5. The server lists Services in the namespace by label, takes the first match, and proxies the request to `{clusterIP}:8089`
6. The solver Pod responds with the key authorization; cert-manager marks the challenge solved

Note: `last_seen_challenge` is stored by the controller but is not currently used by the challenge handler — the server resolves the backend purely by the Service label selector.

Note: the server assumes only one solver Service is active at a time (takes the first result from the label query, with no guaranteed ordering). This breaks if multiple HTTP-01 challenges are active simultaneously in the namespace — e.g. a Certificate with multiple SANs, or two Certificates renewing concurrently. Planned to be addressed.

## Architecture

Two concurrent Tokio tasks run in `main.rs`:

**Challenge Controller** (`src/challenge_controller.rs`)
- Kubernetes controller using `kube-rs` runtime watching `Challenge` CRDs in a configured namespace
- On reconcile, stores the current challenge in shared `LastSeen<Option<Arc<Challenge>>>` state
- Uses finalizers (`challenge_server` finalizer name); error policy requeues with 30s backoff

**Challenge Server** (`src/server.rs`)
- Axum HTTP server on `0.0.0.0:<PORT>`
- `GET /.well-known/acme-challenge/{token}` — proxies to the cluster IP of the first Service labeled `acme.cert-manager.io/http01-solver=true` at port 8089
- `GET /healthz` — health check
- All other requests redirect to HTTPS using the `DOMAIN` env var as the authority

**Shared state** (`ChallengeServerState`):
- `reqwest_client` — HTTP client for proxying to backend solver pods
- `service_api` — Kubernetes Service API client (namespaced)
- `last_seen_challenge` — `&'static LastSeen<Option<Arc<Challenge>>>` (leaked `Box`); `LastSeen` is a `Mutex<Cell<Observed<T>>>` wrapper defined in `main.rs`

**CRD** (`src/crds/challenge.rs`) — auto-generated by Kopium from cert-manager's Challenge CRD. Do not edit manually.

## Required RBAC Permissions

The service account running this Pod needs:

| Resource | API Group | Verbs |
|---|---|---|
| `challenges` | `acme.cert-manager.io` | `get`, `list`, `watch`, `patch`, `update` |
| `services` | `""` (core) | `get`, `list` |

## Environment Variables

| Variable    | Default | Description                          |
|-------------|---------|--------------------------------------|
| `NAMESPACE` | `lec`   | Kubernetes namespace to watch        |
| `PORT`      | `80`    | HTTP server listen port              |
| `DOMAIN`    | —       | Required. Domain for HTTPS redirects |

## Kubernetes Version Feature Flags

The `k8s-openapi` dependency requires a compile-time feature to select the Kubernetes API version: `v1_31`, `v1_32`, `v1_33`, `v1_34`, `v1_35` (default). Only one may be active at a time.

## Cryptography

Uses `aws-lc-rs` as the default rustls crypto provider (post-quantum capable). FIPS support is planned but not yet implemented (requires cmake and Go toolchain).
