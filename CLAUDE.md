## Project Overview

A Rust-based Kubernetes ACME HTTP-01 challenge solver that integrates with cert-manager. It watches Challenge CRDs and serves ACME challenge responses, acting as a custom HTTP-01 solver for cert-manager's certificate issuance flow.

## Build Commands

```bash
# Build (default: Kubernetes v1.35)
cargo build --release

# Build for a specific Kubernetes version
cargo build --features v1_31 --release   # supports v1_31 through v1_35

# Docker build
docker build --build-arg K8S_VERSION=v1_35 .
```

There are currently no tests or linting configuration beyond `cargo check` / `cargo clippy`.

## Architecture

Two concurrent Tokio tasks run in `main.rs`:

**Challenge Controller** (`src/challenge_controller.rs`)
- Kubernetes controller using `kube-rs` runtime watching `Challenge` CRDs in a configured namespace
- On reconcile, updates shared `LastSeen<Option<Arc<Challenge>>>` state with the current active challenge
- Uses finalizers; error policy requeues with 30s backoff

**Challenge Server** (`src/server.rs`)
- Axum HTTP server on `0.0.0.0:<PORT>`
- `GET /.well-known/acme-challenge/{token}` — proxies to a backend Kubernetes Service labeled `acme.cert-manager.io/http01-solver=true` (port 8089), using the last-seen Challenge from shared state to resolve the correct service
- `GET /healthz` — health check
- All other requests redirect to HTTPS

**Shared state** (`ChallengeServerState`):
- `reqwest_client` — HTTP client for proxying to backend solver pods
- `service_api` — Kubernetes Service API client
- `last_seen_challenge` — `Arc<RwLock<Option<Arc<Challenge>>>>` shared between controller and server

**CRD** (`src/crds/challenge.rs`) — auto-generated by Kopium from cert-manager's Challenge CRD. Do not edit manually.

## Kubernetes Version Feature Flags

The `k8s-openapi` dependency requires a compile-time feature to select the Kubernetes API version: `v1_31`, `v1_32`, `v1_33`, `v1_34`, `v1_35` (default). Only one may be active at a time.

## Cryptography

Uses `aws-lc-rs` as the default rustls crypto provider (post-quantum capable). FIPS support is planned but not yet implemented (requires cmake and Go toolchain).
